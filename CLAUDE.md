# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repo này

`OpenViCloud/titan-control-plane` là control plane của Titan (ASP.NET Core 9): REST API `/v1`, identity, tenancy, quota, billing, ví, và bảng lệnh `core.provider_commands` mà [`titan-incus-worker`](https://github.com/OpenViCloud/titan-incus-worker) lease qua `/internal`. Repo này chỉ chứa code, test, `api/openapi-v1.json` và CI của control plane. Gate "không phá `/v1`" là `.github/workflows/ci-api.yml`; repo CLI, provider và `titan-landing` chép spec từ repo này (`scripts/sync-spec.sh <sha>` của từng repo).

Doc ở lại repo `OpenViCloud/titan-ops` (private): luật kiến trúc (`docs/architecture/`), design + user story từng feature (`docs/features/`), hạ tầng, iteration, release, gitops và quy trình (skill `.claude/commands/`). Comment và file này nêu một doc của titan-ops bằng từ khoá `titan-ops <đường dẫn dưới docs/>#<anchor>` (`titan-ops architecture/code-comments.md#private-repo-refs`), không bằng URL: repo này public, link vào titan-ops là 404 với người ngoài; step CI "No URL into private titan-ops" đỏ khi có URL. Ngoại lệ: 45 đường dẫn `docs/…` (43 dòng) nằm trong **chuỗi** (thông điệp assert của guard, thông điệp health check và log, văn bản pháp lý `LegalDocumentCatalog`) giữ nguyên chữ, là đường dẫn trong repo titan-ops — đổi chuỗi là đổi hành vi (văn bản pháp lý đổi thì phải tăng `Version`). Iteration và release chạy từ phiên ở titan.

```
Control Plane (.NET)  →  core.provider_commands  →  incus-worker (Go)  →  Incus 7.0
```

## control-plane Architecture

Clean Architecture: `Titan.Host` → `Titan.Application` → `Titan.Domain` ← `Titan.Infrastructure`

- `Titan.Host` — `Program.cs` only: DI registration, middleware pipeline, `app.Run()`. No business logic, no endpoints.
- `Titan.Application` — Services + DTOs. Provider commands are enqueued here (`IProviderCommandQueue`). **Validators do NOT live here** — xem mục dưới.
  - **Gốc `Titan.Application/` chỉ có 3 nhánh + 2 thư mục port** (`titan-ops architecture/code-structure.md#application-tree` · `titan-ops architecture/code-structure.md#services-branch`): `Commands/` · `Queries/` · `Services/` · `Abstractions/` · `Options/`. Module (`Billing` · `Platform` · `Catalog` · `Compute` · `Networking` · `Admin`) là **segment thứ hai** của mỗi nhánh. Namespace khớp folder: `Titan.Application.Services.Billing.TopUp`, … Guard `ApplicationRoot_HoldsOnlyTheThreeBranchesAndTwoPortFolders` đỏ khi một thư mục thứ sáu mọc ở gốc.
    - 🔑 **`Commands/` và `Queries/` là trục BẬC MỘT** (`titan-ops architecture/code-structure.md#application-tree` + `titan-ops architecture/code-structure.md#contracts`): `Commands/<Module>/<Aggregate>/` và `Queries/<Module>/<Aggregate>/`, contract trong `Contracts/` của **chính bên đó**. Handler `*CommandHandler`/`*QueryHandler` (**cả type lẫn tên file**), method luôn `HandleAsync`, **không** interface, DI thủ công từng dòng ở `Program.cs`. **Không** MediatR (`Send()` cắt go-to-definition = sai chính mục tiêu).
    - 🔴 **Contract hai bên KHÔNG được reuse** (`titan-ops architecture/code-structure.md#no-contract-reuse`) — kể cả khi field trùng. Guard `NeitherSide_TouchesTheOthersContracts` canh **chữ ký** (param + return, unwrap `Task<>`/`List<>`); nó **không** canh nội dung thân hàm. Hệ quả có thật: `RenameVm` **không trả gì** (caller đọc lại bằng `GetVmQuery`) — đó là cách gỡ nguồn ràng buộc thay vì nhân đôi record. **Đừng** nới luật này.
    - 🔑 **Command không trả dữ liệu** (`titan-ops architecture/http-contract.md#commands-return-no-data`, Tôn Chủ chốt 2026-09-23, **toàn repo**): **mọi PUT/PATCH → `204` không body** (22 route — 16 lúc chốt + `intents/{id}/failed` của INTENT-4 + `internal/tenants/{id}/provider-account` của DESIRED-CURRENT-STATE PR-4 + `admin/clusters/{id}/provider-settings` của MULTI-ZONE − `PUT admin/clusters/{id}` và `PUT admin/clusters/{id}/provider-settings` gỡ ở ZONE-TO-CLUSTER (cluster đọc từ config) − 2 route tài khoản tenant (`provision`, `provider-account`) gỡ ở INCUS-2 + 4 route lease `internal/provider-commands/leases/{leaseId}[/completion|/failure]` + `PUT tenant/load-balancers/{id}` + `internal/load-balancers/{id}/status` của NETWORK-LOAD-BALANCER + `PATCH tenant/load-balancers/{id}` (đổi tên) của TERRAFORM-PROVIDER − `PUT admin/backup-target` (thêm rồi gỡ trong BACKUP-RESTORE: target đọc từ cấu hình pod) — kể cả `/internal/*` — worker chấp nhận mọi 2xx) · **POST action async** (`pay`/`settle-from-wallet`/`topups/{id}/confirm` — tiền còn trong outbox `titan-ops architecture/money-and-wallet.md#single-writer-outbox`; `admin/templates/sync` — enqueue, worker reconcile sau, **CQRS-5 `D-5`**, admin portal đọc lại bảng template thay vì số đếm) → **`202` không body** · create → id-only body (`titan-ops architecture/http-contract.md#create-returns-id`) — **7 create `202`** (VM · volume · network · 2 snapshot · restore · load balancer: tài nguyên chờ provider) · **5 create `201`** (firewall rule · topup · grant · SSH key · token API). Handler phía command trả `Task`; endpoint `Endpoint<TReq>` không `TResponse`. Ngoại lệ **duy nhất** có tên: SePay webhook (`200 {success:true}` — hợp đồng của SePay). Guard `CommandHttpContractTests` (FullHost) lấy danh sách PUT/PATCH từ `EndpointDataSource` thật + `PutAndPatchRoutes = 22`; nửa status-code là phép đo **văn bản** (im lặng về `Response.StatusCode = …` gán tay). PUT/PATCH mới "cần" body ⇒ **dừng hỏi Tôn Chủ** (`T-1`), đừng thêm ngoại lệ. Spec OpenAPI khai đúng mã thành công (`SuccessCodeSpecTests`) và enum trạng thái (`StateEnumSpecTests`) — `titan-ops features/public-api/design.md#success-codes` · `titan-ops features/public-api/design.md#state-enums`; mã `4xx` chưa khai.
    - `*Command` **LÀ** wire contract (`titan-ops architecture/code-structure.md#command-is-wire-contract`): endpoint bind thẳng, `CreateVmValidator : Validator<CreateVmCommand>`. Route mang `{vmId}` thì body không chứa nó ⇒ record body nhỏ (`RenameVmBody`/`UpdateVmStatusBody`) ở **cạnh endpoint** trong Infrastructure, command mang cả hai.
    - Handler trong `Queries/` **không được** inject `IProviderCommandQueue`/`IActivityRecorder` — guard `ReadWriteSeparationTests`, mutation-checked. `Titan.Application/Shared/` **chưa tồn tại**: luật cho phép enum dùng chung ở đó, nhưng chưa có ca (`VmStatus` là enum của Domain) — đừng tạo rỗng (`T-7`, Athena).
    - **Đã tách xong**: Compute (`CQRS-1`/`CQRS-2`) + **Billing** (`CQRS-3`, 9 command + 10 query). Hành vi dùng chung giữa handler (handler **cấm** gọi handler — `Handlers_DoNotReferenceOtherHandlers`) nằm ở **`Services/<Module>/`** dạng static (`titan-ops architecture/code-structure.md#services-branch`; trước SVC-TREE 2026-09-25 nằm ở gốc module), theo tiền lệ `Services/Compute/ComputeOwnership.cs`: `Services/Billing/TopUp/TopUpConfirmation` (admin confirm + SePay) · `Services/Billing/Invoice/InvoiceWalletSettlement` (pay + settle) · `Services/Billing/Invoice/InvoicePaymentStates` (3 query hoá đơn). Job nền Billing **không** thành handler — chỉ đổi chỗ ở: `Services/Billing/Metering/` (3 meter `IMeter`) + `Services/Billing/WalletMutations/` (**số nhiều có chủ ý**: `WalletMutation/` trùng class Domain ⇒ `CS0118`). **Platform** (`CQRS-4`, 7 command + 7 query): `Services/Platform/Tenant/CurrentTenant` (static, `GetTenant` + `ListTenantMembers` dùng chung); `ActivityRecorder` + `IdempotencyService` + `LegalDocumentCatalog` ở `Services/Platform/` (`ActivityEvent/` · gốc · `Legal/`) — hạ tầng, không phải use-case. `BootstrapTenant`/`ApproveDeclaredAccount` **không** có endpoint: `TenantResolutionMiddleware` inject hai handler này (+ `OpenWalletCommandHandler`) ⇒ thiếu một dòng DI là **mọi** request đã đăng nhập 500. ⚠️ **`Legal/` là ngoại lệ có tên** với "thư mục handler = aggregate Domain" (aggregate là `Acceptance`; Tôn Chủ chọn `Legal/` khớp `Endpoints/Legal/` — CQRS-4 `D-2`). **Networking · Catalog · Admin** (`CQRS-5`, 12 command + 12 query) ⇒ 🔑 **chuỗi CQRS ĐÓNG: không còn `*Service.cs` use-case nào ở tầng Application**; static/hạ tầng/job có tên nay ở `Services/` (`titan-ops architecture/code-structure.md#services-branch`). `Services/Networking/Network/NetworkOwnership` (static, 6 đường ownership network → 404, `CQRS-DEBT-2` phần network đóng). `Services/Catalog/VmTemplate/TemplateSyncRunner` là **job** (không phải handler) inject `SyncTemplatesCommandHandler`. `Admin/` gốc **không còn** — handler ở `Commands|Queries/Admin/{Vm,Network}/`, vẫn chỉ đọc RA 3 module. Thư mục theo aggregate (`VmTemplate/`, `Network/`; `Networking/FirewallRule/` là ngoại lệ có tên — child entity có route và callback riêng, `titan-ops architecture/code-structure.md#child-entity`); ⚠️ **2 ngoại lệ có tên** nữa: `Queries/Catalog/{Cluster,OsImage}/` không có aggregate (config + đọc live Incus), trả thẳng kiểu port `ClusterInfo`/`OsImageInfo` của `Abstractions/`. `CatalogLookupService.ListTemplatesAsync` (0 caller) **đã bỏ**; `IComputeCatalogProvider.ListTemplatesAsync` cũng bỏ ở INCUS-2 PR-2b. 5 bản `GetOwnedVmAsync` private của handler Vm (CQRS-1) **đã gom** về `ComputeOwnership.RequireVmAsync` (`INTENT-1` `D-13`) ⇒ **`CQRS-DEBT-2` ĐÓNG** — lệnh đo của retro CQRS-5 ra 0.
    - 🔑 **`Services/<Module>/[<Aggregate>/]` = mọi thứ KHÔNG phải handler** (`titan-ops architecture/code-structure.md#services-branch`, SVC-TREE 2026-09-25): static dùng chung giữa handler (handler **cấm** gọi handler), job nền, hạ tầng. Tầng hai theo **aggregate** như `Commands/` (`Services/Billing/TopUp/TopUpConfirmation`); file phục vụ **nhiều** aggregate hoặc không aggregate nào ở gốc module (`Services/Compute/ComputeOwnership` — 4 aggregate · `Services/Platform/IdempotencyService` · `Services/Billing/BillingConstants`); 2 thư mục job giữ tên (`Metering/` · `WalletMutations/`). Thư mục trùng tên aggregate Domain ⇒ alias `XAggregate` (tiền lệ `Commands/Billing/TopUp/`). ⚠️ Đây **không** phải tầng `Services/` cũ đã gỡ trong chuỗi CQRS — cái đó chứa **use-case** (nay là handler); đừng đặt use-case mới ở đây. 🔴 `"Services"` phải nằm trong `Branches` của **cả** `ModuleBoundaryTests.ModuleOf` **và** `QuotaOwnershipTests` — thiếu là type **vô hình**, guard xanh sai (mutation đo: `EveryModule_IsSeenByTheScan` + `Allowlist_HasNoStaleEntries` đỏ).
    - ⚠️ `Abstractions/` và `Options/` ở gốc **không phải module** — khai tường minh ở `QuotaOwnershipTests.NonModuleDirs`. Guard ranh giới module **không đo** nội dung hai thư mục này (`SePayOptions` thuộc Billing về nghĩa nhưng nằm ngoài mọi phép đo cạnh chéo) — nợ có tên, owner Athena (`titan-ops architecture/code-structure.md#debt-and-accepted-risks`).
    - 🔑 **`Admin/` là nhóm thứ 6 ở Application; Domain không có tầng module** — bất đối xứng **có chủ ý** (`titan-ops architecture/code-structure.md#admin-read-model`). Các handler Admin (từ CQRS-5; trước đó là `AdminResourceService`) là read-model/BFF cho admin portal, cộng việc xuyên tenant của nền tảng (`Admin/Backup`: lịch backup VM/volume và health của chúng): chúng **đọc ra** 3 module và **không ai đọc vào chúng** ⇒ đồ thị phụ thuộc **hết chu trình**. Đừng "sửa" cho đối xứng.
  - ⚠️ Tên **module** (segment thứ hai) **không được trùng tên type trong `Titan.Domain`** — `Networking/` chứ không phải `Network/`, vì C# resolve về namespace trước type (`CS0118`); có test canh. Tầng **aggregate** (segment thứ ba) thì **cố ý** trùng — giải bằng alias `XAggregate`.
  - *(Lịch sử — trước chuỗi CQRS; nay chỉ còn `IdempotencyContracts`/`TemplateSyncContracts`/`MeterHeartbeatContracts` theo luật này)* DTO/contract type ở **file riêng cạnh service**, cùng folder và **cùng namespace**: `Services/Platform/IdempotencyService.cs` + `Services/Platform/IdempotencyContracts.cs`. Cùng namespace là có chủ ý — consumer cần **một** `using`, không phải hai. **Không** có folder `Contracts/` (folder riêng sẽ làm folder ≠ namespace, hoặc bắt hàng trăm file thêm `using`).
  - Quy tắc tách là **cơ học, không phán đoán theo tên**: `record` = contract (đi ra `*Contracts.cs`) · `interface`/`class`/`enum` = hành vi (ở lại).
- `Titan.Domain` — Aggregates + domain exceptions + repository interfaces + `Model/` (base class vai trò).
  - `Aggregates/` có **một tầng**: thư mục aggregate (`titan-ops architecture/code-structure.md#domain-tree` + `titan-ops architecture/code-structure.md#aggregate-is-a-folder`) — `Aggregates/<Aggregate>/<Type>.cs`, namespace `Titan.Domain.Aggregates.<Aggregate>`, **một public type một file**. Không tầng module: module chỉ có ở `Titan.Application/`.
    - 🔑 **Aggregate là thư mục, và thư mục ấy phải chứa root cùng tên.** Có test canh (`Titan.Tests/Domain/AggregateBoundaryTests.cs`, 3 test): type nằm đúng `Titan.Domain.Aggregates.<Aggregate>`, không tầng nào khác · thư mục aggregate phải có root cùng tên · một public type một file. Guard này canh thư mục (`titan-ops architecture/code-structure.md#domain-tree`); vai trò root/child đọc từ base class (bullet dưới), không từ một bảng prose.
    - 🔑 **Vai trò của type là base class** (`titan-ops architecture/code-structure.md#domain-base-classes`): root `: AggregateRoot`, child `: ChildEntity`, value object `: ValueObject` (`abstract record`) — cả ba **rỗng** ở `Titan.Domain/Model/`, không `Id`, không `Equals`. Guard `Titan.Tests/Domain/DomainBaseClassTests.cs` (4 test): mọi class/record/struct không static ở `Aggregates/` và `Values/` có vai trò, hoặc nằm trong `NoRole` kèm lý do (record chở input/kết quả của một lời gọi) · root là class trùng tên thư mục, và chỉ nó · không value object nào có `set`/`init` public. Value object mới viết là `sealed record : ValueObject`, property `{ get; private init; }`.
    - Child là type `: ChildEntity` (guard trên đọc nó, không đọc danh sách này). Năm child cần biết: `VmTemplateCluster` (trong `VmTemplate/` — trạng thái sync của template ở **một** cluster, khoá `(template_id, cluster_id)`, `titan-ops features/catalog/design.md#template-per-cluster`) · `LoadBalancerListener` + `LoadBalancerBackend` (trong `LoadBalancer/` — mỗi hàng mang `IsDesired`/`IsApplied`, `titan-ops features/load-balancer/design.md#lb-resource-model`). `FirewallRule` (trong `Network/`, `titan-ops architecture/code-structure.md#child-entity`: cap per network đếm trong `Network.FirewallRuleQuotaUsage`, handler đi qua `Network.AddFirewallRule`/`RequestFirewallRuleDelete`/`MarkFirewallRule*`, `INetworkRepository` load kèm rule, `FindByIdForUpdateAsync` khoá hàng network khi thêm rule, `IFirewallRuleRepository` chỉ đọc). `VolumeSnapshot` (trong `Volume/`, DCE-2: cùng mẫu — `Volume.AddSnapshot`/`RequestSnapshotDelete`/`BeginSnapshotRestore`/`MarkSnapshot*`, `RequestDelete()` tự đếm snapshot sống, `IVolumeSnapshotRepository` chỉ đọc). Còn lại là root riêng — `VmSnapshot` **là root** tới DCE-3 của DOMAIN-CHILD-ENTITIES.
    - ⚠️ Thư mục aggregate **cố ý trùng tên** với root của nó (`Vm/` chứa `class Vm`). Consumer dùng `using` **sâu** thì compile bình thường. Nhưng tham chiếu **bán-định-danh** `Domain.Aggregates.Vm.Create(...)` sẽ ăn `CS0118` — phải viết `...Vm.Vm.Create(...)`. Trong Domain, aggregate là namespace anh em của nhau ⇒ tên root trần (`Tenant`) resolve về namespace: dùng alias `using TenantAggregate = Titan.Domain.Aggregates.Tenant.Tenant;`. Luật cấm trùng tên thư mục nay **hẹp lại**: được trùng tên với type **nằm bên trong nó**, trùng với type khai nơi khác vẫn đỏ.
    - ⚠️ **Không gọi các nhóm module của `Titan.Application` là "bounded context"** — sai một cấp. Chúng là module/subdomain trong **một** bounded context: một `Tenant` dùng chung, một `TitanDbContext`, một assembly.
  - `ProviderCommand` (hàng bảng lệnh xuống provider, `titan-ops architecture/provider-and-worker.md#provider-command-table`) là aggregate riêng (`Aggregates/ProviderCommand/`); handler của nó ở `Platform/` của Application, **không** ở `Compute/`. Cluster **không** phải aggregate: nó là config `Clusters__N__*` (`ClusterOptions`, validate lúc khởi động) — id, tên, endpoint, fingerprint server, cấu hình provider (`titan-ops features/cluster/design.md#cluster-from-config`); danh tính TLS client của Titan là Secret `ProviderClientIdentity__CertificatePem`/`__KeyPem` (`ProviderClientIdentityStore`, singleton) (`titan-ops features/cluster/design.md#provider-client-identity`).
  - Hai invariant có **test canh** (`Titan.Tests/Domain/DomainFolderConventionTests.cs`): (a) tên thư mục không trùng tên public type trong `Titan.Domain` (`CS0118`), (b) namespace khớp đường dẫn folder.
  - 🔑 **`TenantQuota` là Value Object đầu tiên của Titan** (`titan-ops architecture/tenancy-and-admin.md#tenant-quota`) — nay là một trong các VO (vd: `Rate`, `titan-ops architecture/money-and-wallet.md#rate-value-object`; `Money` đã thành `long`, xem bullet dưới). **9** cap của một tenant trong **một** value, map bằng `ComplexProperty` (9 cột trong `core.tenants`, không entity riêng). Property là `{ get; private init; }` **có chủ ý**: positional record sinh `with` **public** ⇒ `quota with { MaxVms = -1 }` dựng được quota không hợp lệ **không đi qua `Create`**. Ngoài vào phải qua `Create` hoặc `WithVmAndNetworkCaps`.
    - **`0` nghĩa là "không được cái nào", KHÔNG phải "vô hạn"** (`>=`, không `>`). 9 cap: `MaxVms`/`MaxNetworks`/`MaxVolumes`/`MaxPublicIpv6`/`MaxSshKeys`/`MaxLoadBalancers` (per **tenant**) · `MaxVmSnapshotsPerVm` · `MaxVolumeSnapshotsPerVolume` · `MaxFirewallRulesPerNetwork`.
    - **Service ĐẾM, `Tenant` QUYẾT — nay TRONG factory** (`titan-ops architecture/code-structure.md#tenant-typed-edge`, `CM-5` ĐÓNG HẲN): `Vm.Create(tenant, activeVmCount, …)` gọi `tenant.EnsureCanCreateVm(activeVmCount)` **bên trong factory**. `activeCount` vẫn từ caller (kết quả query, không thuộc aggregate) cho cap per tenant; cap theo cha (`Network.AddFirewallRule`, `Volume.AddSnapshot`) đếm trên child cha đang cầm (`titan-ops architecture/code-structure.md#child-entity`), nhưng lời **gọi** không còn skip được: 9 `EnsureCanX` nay **`internal`** ⇒ **compiler** chặn `Titan.Application` (`CS1061`), và factory không trả ra entity nếu chưa qua check. "Quên gọi = không có VM để trả." **8 → 0** call site gọi từ service. Guard: 9 dòng `→ Tenant` của `AggregateEdgeAllowlist` + `DomainAggregates_ReferenceOtherAggregatesOnlyThroughTheAllowlist`.
    - `PATCH /v1/tenants/{id}/quota` nhận đủ 9 cap; 7 cap ngoài `maxVms`/`maxNetworks` **tuỳ chọn, vắng ⇒ giữ** giá trị của chính tenant (`UpdateTenantQuotaCommandHandler.KeepOrReplace`) — dựng VO từ `Default` hay từ thứ request mang là đường **mất dữ liệu im lặng**. `GET /v1/tenants` (admin) trả `AdminTenantQueryResult` đủ 9 cap; `GET /v1/tenant` (khách, trong OpenAPI) vẫn 4 cap — nợ có tên ở tenant design (`titan-ops features/tenant/design.md`).
  - **Ngôn ngữ chung**: `titan-ops domain/ubiquitous-language.md` — Ubiquitous Language đầy đủ (actor/compute/network/catalog/billing/quota). Giữ khớp `Titan.Domain/Aggregates/` **thủ công**: guard `UbiquitousLanguageTests` **đã gỡ 2026-09-10** khi mở rộng doc (nó chỉ đo **TÊN** không đo **NGHĨA**, `Q-5`). 🔑 **`Amount` có 5 nghĩa ở 5 aggregate** (§5.1), và `WalletTransaction.Amount` là cái **duy nhất âm được** — đọc nó như 4 cái kia là biến một lần trừ tiền thành cộng tiền.
  - 🔑 **Số tiền là `long` (VND nguyên), KHÔNG còn value object** (`titan-ops architecture/money-and-wallet.md#money-is-long-vnd`) — VND không có đơn vị lẻ ⇒ `Money` kiểu `decimal` mô hình độ chính xác không tồn tại. `struct Money` + `MoneyEnumerableExtensions` **đã xoá**; **9** property tiền là `long` **có dấu** (`WalletTransaction.Amount` giữ âm cho debit) — `UsageRecord.Cost` **không** còn là tiền: tích thô `decimal(18,10)` (migration `UsageCostIsRaw`), làm tròn một lần ở dòng hoá đơn (`titan-ops architecture/money-and-wallet.md#round-once`). Cột tiền `decimal(18,10)→bigint` từ migration `MoneyIsLongVnd`, **không** ABS/CHECK — non-negative là invariant của **từng aggregate**, không của kiểu lưu. DTO ra API **giữ `decimal`** (`titan-ops architecture/money-and-wallet.md#money-is-long-vnd`), cast `(long)` ở service boundary. ⚠️ `long` có dấu ⇒ reconciliation `SUM(amount)==available_amount` **không đổi** (WAL-DDD-01/`titan-ops architecture/money-and-wallet.md#wallet-one-balance` nguyên vẹn).
  - 🔑 **`Rate` VẪN là value object ở `Titan.Domain/Values/`** (`titan-ops architecture/money-and-wallet.md#rate-value-object`, `CM-3` đóng): `sealed record : ValueObject`, bằng nhau theo `PerUnit`, chỉ dựng qua `Rate.Of` — chỉ còn **`Rate.cs`** ở `Values/` (Money đã rời). `Rate` bọc **4** đơn giá (`PricePerHour`/`PricePerGbPerHour`/…), tất cả `decimal(18,10)`. `Rate × decimal → decimal` **thô**; `UsageRecord.Cost` giữ tích thô; `UsageRecord.TotalVnd` làm tròn half-away-from-zero **một lần trên tổng của một dòng hoá đơn** (làm tròn từng bản ghi 10 phút từng tính snapshot và volume nhỏ 0 ₫). Map bằng **`RateConverter`** ở `TitanDbContext.ConfigureConventions` (`MoneyConverter` đã bỏ), **không** `ComplexProperty`. ⚠️ **Risk-accepted** (bảng Nợ của money-and-wallet): compiler **hết** chặn trộn giá với số dư phía `long` (khi `Money` còn là type thì chặn được) — guard `MoneyAndRateTests` (reflection) nay chỉ canh phần `Rate` giữ lại (không conversion/additive op, `Rate×decimal` trả `decimal`) + `ModuleBoundaryTests.SharedValueTypes_KnowAboutNoAggregate` (Values không được biết aggregate nào).
  - `Repositories/` (interface) **phẳng**: `Titan.Domain/Repositories/I<X>Repository.cs`, namespace `Titan.Domain.Repositories` (`titan-ops architecture/code-structure.md#repositories-by-module`). Module của mỗi repository (cho guard Application) là dòng của nó trong bảng `RepositoryModule` của `ModuleBoundaryTests`, không phải thư mục.
    - 🔑 **Ranh giới module có test canh** (`Titan.Tests/Domain/ModuleBoundaryTests.cs`, `titan-ops architecture/code-structure.md#module-boundary` · `titan-ops architecture/code-structure.md#application-edge-allowlist` · `titan-ops architecture/code-structure.md#tenant-typed-edge` · `titan-ops architecture/code-structure.md#shared-value-types`): mỗi repository có đúng một dòng `RepositoryModule`, dòng thừa đỏ · aggregate không trỏ type sang aggregate khác, trừ dòng `AggregateEdgeAllowlist` kèm lý do (fail cả hai chiều): 9 dòng `→ Tenant` từ **factory param** (`titan-ops architecture/code-structure.md#tenant-typed-edge`); 5 dòng của luật chéo hai aggregate (`LoadBalancer`, `VmSnapshot`, `Volume` → `Vm`; `Volume ↔ VolumeSnapshot` hết là cạnh chéo từ DCE-2) và 3 dòng `InvoiceItem` → `UsageResourceType` (enum của `UsageRecord`) · type ở `Titan.Domain/Values/` **không được biết aggregate nào** (`SharedValueTypes_KnowAboutNoAggregate`, `titan-ops architecture/code-structure.md#shared-value-types`) · mọi ctor dependency chéo module phải có trong **allowlist kèm lý do** · allowlist có dòng mô tả cạnh **đã chết** cũng **đỏ** · guard phải **thấy** nhóm `Admin` · **0 dòng `DEBT:`** · **0 chu trình** (DFS, không đọc bảng bằng mắt).
    - 🔴 **Một nhóm namespace KHÔNG có trong `ApplicationModules` là VÔ HÌNH, không phải "ngoài luật".** `ModuleOf()` trả `null` cho segment nó không nhận ra ⇒ guard có thể **xanh** trong khi cạnh chéo vẫn tồn tại nhưng không được đo. Gốc `Titan.Application/` **đóng** ở 5 thư mục — thư mục thứ sáu đỏ `ApplicationRoot_HoldsOnlyTheThreeBranchesAndTwoPortFolders` bất kể khai ở đâu. **Module mới** vào làm segment thứ hai dưới một nhánh **và** phải khai trong `ApplicationModules` — guard `EveryModule_IsSeenByTheScan` chỉ canh **chiều thứ nhất** (module **đã khai** phải được scan thấy); segment **chưa** khai vẫn vô hình (`titan-ops architecture/code-structure.md#guard-sees-every-module`).
    - ⚠️ **Guard đo CẠNH giữa module, không đo SỐ PARAM đi qua cạnh.** Thêm một dependency qua cạnh **đã có sẵn** thì guard xanh không cần sửa dòng nào ⇒ **lý do** của một dòng allowlist lệch dần, và **không phép đo nào** cho "lý do đúng" — phải sửa tay.
    - **11 cạnh chéo module** hợp lệ ở `Application` (allowlist là nguồn sự thật; Context Map (`titan-ops domain/context-map.md`) giải thích *vì sao*). **0 chu trình** và **0 dòng `DEBT:`** — 2 chu trình cũ (`Platform↔Compute`, `Platform↔Networking`) sinh từ **một** type `AdminResourceService`; nó ra `Admin/` nên cạnh **đổi chiều**, không mất đi.
    - ⚠️ Guard chỉ đọc **constructor param** và **type reference**. Method param / static / service locator: **vô hình**. Hai module trao đổi qua `Guid` trần vẫn coupling — **allowlist xanh ≠ hết coupling**.
- `Titan.Infrastructure` — EF Core + PostgreSQL, `ProviderCommands/ProviderCommandQueue` (ghi `core.provider_commands`), `Incus/` (`IncusClient` mutual TLS ghim fingerprint, `IncusCatalogProvider`, tester), **FastEndpoints classes** in `Endpoints/` (HTTP adapter layer)

**Error response shape:** `{ status, title, code }` — error code (e.g. `VM_QUOTA_EXCEEDED`) is in `code`, not `detail`.

**Auth:** bearer `ovc_…` = token API của một member (scheme `ApiToken`, principal chỉ `sub`), bearer khác = JWT Keycloak (`titan-ops features/public-api/design.md#api-token`).

**Middleware pipeline:** `UseWebSockets` → `UseAuthentication` → `TenantResolutionMiddleware` → `UseAuthorization` → `IdempotencyMiddleware` → `UseFastEndpoints`. The middleware resolves `TenantId` from DB (not JWT) and short-circuits with `403 TENANT_SUSPENDED` for write operations when tenant is suspended — a websocket upgrade (SSH session) counts as a write.

**FastEndpoints:** HTTP endpoints live in `Titan.Infrastructure/Endpoints/`. Base class is `Endpoint<TRequest, TResponse>` (or `EndpointWithoutRequest`). Route params bound via `Route<T>("paramName")`. Auth configured per-endpoint: `AllowAnonymous()`, `Roles("platform-admin")`, or default (requires auth). **Validators live HERE, next to their endpoint** — `class XValidator : Validator<XRequest>` cùng file endpoint hoặc file `*Validator.cs` cùng thư mục (FastEndpoints' `Validator<T>`, tự động discover, chạy trước `HandleAsync`). **Không có validator nào trong `Titan.Application`.** Validation errors return `{ status: 400, title, code: "VALIDATION_ERROR" }`.

**Test pattern — service-level, stub-first; doubles only in unit tests** (`titan-ops architecture/testing.md#doubles-only-in-unit-tests`, guard `DoublePlacementTests`): `Category=Integration` and `Category=FullHost` run real implementations — Postgres via `Titan.Tests/Infrastructure/Integration/TestPostgres.cs` (one FullHost case runs with no database on purpose) — no Moq, no `Fakes/`, no InMemory, no replaced host service.
- Tests target the handlers directly (CQRS; the older `*ServiceTests` files keep their call shape through a small private facade over the real handlers) — no HTTP layer, no `WebApplicationFactory`.
- Prefer **stubs** (concrete class implementing interface, fixed return values, no call verification) over mocks.
- Use **Moq mocks** only when call verification is required (e.g. assert `IProviderCommandQueue.EnqueueVmCreateAsync` was called exactly once with specific args).
- Test files: `Titan.Tests/Services/*ServiceTests.cs`, `Titan.Tests/Auth/TenantResolutionMiddlewareTests.cs`.
- **Endpoint-level tests** — an endpoint that only forwards to a service needs no test of its own; the service test covers it. An endpoint that carries **its own logic** (parsing, composing, auth gating, enriching) gets one, using `FastEndpoints.Factory.Create<TEndpoint>(...)` — no host, no DB. Examples: `GetTenantBillingSummaryEndpointTests.cs`, `SyncTemplatesEndpointTests.cs`, `UpdateTemplateStatusEndpointTests.cs`.
  > This rule exists because of `BILL-01`: the billing summary endpoint held enrichment logic that 500'd for any tenant with ≥2 billed VMs, and service-level tests covered none of it. "Service-level only" is right for thin adapters and blind to everything else.
- **Full-host tests** (`WebApplicationFactory` through `Api/RealHostFactory.cs`: the host as `Program.cs` wires it, on its own migrated Postgres) stay reserved for cross-cutting concerns — `CorsTests.cs`, `HealthCheckTests.cs`, `OpenApiSpecTests.cs`, `CatalogContractTests.cs`.
- **Schema/model tests** — DB constraints that carry business meaning (e.g. the idempotency unique index `UNIQUE(resource_type, resource_id, bucket)` behind sampled metering — `titan-ops architecture/money-and-wallet.md#append-only-metering`) are pinned by asserting EF model metadata: `UsageRecordSchemaTests.cs` (this replaced `VmBillingSessionSchemaTests`, gone with `VmBillingSession`). The InMemory provider does not enforce indexes, so this is what guards the migration's intent. Same shape: `WalletSchemaTests.cs`, `TenantQuotaSchemaTests.cs`.

## Key Conventions

### Git Workflow

- **`git worktree` bị CẤM trong project này.** Một repo, một working tree. Skill toàn cục `superpowers:using-git-worktrees` **không áp dụng** — luật này đè nó.
  > Lý do — **cơ chế, không phải một file cụ thể**: worktree tách filesystem nên tách luôn **mọi file không nằm trong git**. Một cây thứ hai không có file gitignored ⇒ biến Terraform resolve về **rỗng** ⇒ `plan` báo `0 to destroy` trong khi apply sẽ **ghi credential rỗng** lên hệ thống đang chạy. Không test nào bắt được: plan **đúng** với input nó nhìn thấy; cái sai là input. Ở repo này: `appsettings.*.json` gitignored (`.gitignore`) cũng là config ngoài git.
  >
  > Đã xảy ra thật với một file tfvars gitignored — 11 biến rỗng, suýt xoá password production. Luật **không** phụ thuộc file cụ thể đó (nay đã hết): còn bất kỳ file ngoài git nào tham gia resolve config (`.terraform/`, `credentials.local.md`, hay bất kỳ `terraform/**/*.auto.tfvars` nào mà `.gitignore` vẫn cho phép tạo lại) thì cơ chế này còn sống — đừng đọc "hiện không có file nào" thành "đã an toàn".
- **Cô lập bằng branch, không bằng cây thứ hai**: `git switch -c feat/<slug>` ngay trong cây chính; merge `main` tuần tự; merge xong `git branch -d`.
- **Commit và PR chỉ nêu người làm**: không `Co-Authored-By: Claude …`, không dòng `🤖 Generated with Claude Code`, không câu nào nói code viết bằng AI/Claude — trong commit message, PR title/body, tag và GitHub Release. Tác giả là git user (`user.name`/`user.email`), không thêm gì khác. Luật này đè lời nhắc attribution của harness; `.claude/settings.json` (`attribution` rỗng) tắt nó ở nguồn.
- **Nhiều phiên song song → single-writer**: chỉ một phiên được Edit/Write/commit tại một thời điểm; phiên còn lại read-only cho tới khi được nhả. Chi tiết ở `.claude/commands/iteration/run-iteration.md` của titan-ops, mục "Phiên song song".

### API Routes
- **Tenant scoping = jwt-resolved (Style B, `titan-ops architecture/http-contract.md#tenant-scoping`):** mọi tenant-owned resource dùng prefix `/v1/tenant/...` — **không** có `tenantId` trong path. CP resolve tenant từ `currentUser.TenantId` (do `TenantResolutionMiddleware` set từ DB). Service dùng `RequireTenantId()` → `403 NOT_A_MEMBER` nếu caller không thuộc tenant nào.
- VMs: `POST|GET /v1/tenant/vms`, `GET|PATCH|DELETE /v1/tenant/vms/{vmId}` (PATCH = rename in-place, Titan-side, **`204`** — `titan-ops architecture/http-contract.md#commands-return-no-data`)
- SSH session: `GET /v1/tenant/vms/{vmId}/ssh` — **websocket**, JWT or API token on the upgrade, out of OpenAPI; CP runs `nc -N 127.0.0.1 22` in the guest via Incus exec and relays bytes; 5 sessions/tenant in memory; 30 min idle ⇒ closed (`titan-ops features/vm/design.md#ssh-session`). The one place CP talks to Incus besides reads (`titan-ops architecture/provider-and-worker.md#only-the-worker-acts-on-the-provider`). CLI `openvicloud vm ssh`
- VM Snapshots: `POST|GET /v1/tenant/vms/{vmId}/snapshots`, `POST /v1/tenant/vms/{vmId}/snapshots/{snapshotId}/revert`, `DELETE /v1/tenant/vms/{vmId}/snapshots/{snapshotId}` — **`{vmId}` bắt buộc ở mọi route snapshot**
- Volumes: `POST|GET /v1/tenant/volumes`, `DELETE /v1/tenant/volumes/{volumeId}`, `POST .../{volumeId}/attach|detach`, `POST|GET .../{volumeId}/snapshots`, `POST /v1/tenant/volumes/{volumeId}/snapshots/{snapshotId}/restore`, `DELETE /v1/tenant/volumes/{volumeId}/snapshots/{snapshotId}` — **`{volumeId}` bắt buộc ở mọi route snapshot**
- Networks: `POST|GET|DELETE /v1/tenant/networks` (`POST` nhận `enablePublicIpv6` — IPv6 public **theo network**, một `/64` của cluster, `titan-ops features/network/design.md#ipv6-public`), firewall rules `/v1/tenant/networks/{networkId}/firewall-rules`
- Load balancers: `POST|GET /v1/tenant/load-balancers`, `GET|PUT|PATCH|DELETE /v1/tenant/load-balancers/{loadBalancerId}` (`PATCH` = đổi tên, chỉ phía Titan, VIP giữ — `titan-ops features/load-balancer/design.md#lb-rename`) — L4 TCP/UDP trên OVN load balancer của Incus, chỉ network đã bật IPv6 public; VIP `<64 của network>::1:n` do Titan cấp; `PUT` = cả cấu hình (listener + backend VM), `204`; miễn phí, quota `MaxLoadBalancers` (`titan-ops features/load-balancer/design.md#vip-in-network-64`)
- API tokens: `POST|GET /v1/tenant/api-tokens`, `DELETE /v1/tenant/api-tokens/{apiTokenId}` — portal sinh bí mật `ovc_…`, control plane chỉ lưu SHA-256; tối đa 20/tenant (hằng số, không quota); xoá cứng; CLI đọc `OPENVICLOUD_TOKEN` (`titan-ops features/public-api/design.md#api-token`)
- SSH keys: `POST|GET /v1/tenant/ssh-keys`, `DELETE /v1/tenant/ssh-keys/{sshKeyId}` — chỉ ở Titan, xoá cứng; tạo VM chọn key qua `sshKeyIds` ⇒ control plane dựng cloud-init vendor-data (script thêm key cho user `ubuntu`), lệnh `vm.create` mang `vendorData` (`titan-ops features/vm/design.md#ssh-key`)
- Billing (tenant): `GET /v1/tenant/billing/summary`, `GET /v1/tenant/vms/{vmId}/cost`, `GET /v1/tenant/billing/invoices[/{invoiceId}]`, **`POST /v1/tenant/billing/invoices/{invoiceId}/pay`** (trả hoá đơn từ ví — `titan-ops architecture/money-and-wallet.md#human-confirmed-debit`)
- Admin (platform-admin, **không** thuộc public contract): `GET /v1/tenants`, `PATCH /v1/tenants/{tenantId}/status`, `PATCH /v1/tenants/{tenantId}/debt-ceiling`, `GET /v1/admin/billing/receivables`, `PATCH /v1/admin/vm-offerings/{offeringId}/price`, `PATCH /v1/admin/invoices/{invoiceId}/pay` (**`MarkPaid` — tiền đến NGOÀI Titan, không đụng ví**), **`POST /v1/admin/invoices/{invoiceId}/settle-from-wallet`** (**trừ ví của tenant, bấm hộ khách** — `titan-ops architecture/money-and-wallet.md#human-confirmed-debit`). ⚠️ Hai route cuối **cố ý khác nhau**; gộp chúng là làm audit log mất khả năng phân biệt ai tiêu tiền của ai
- Catalog (global): `GET /v1/clusters` (anonymous, từ config) · `GET /v1/templates[?clusterId=]` (chỉ template **listed** — `titan-ops features/catalog/design.md#template-listed`; có cluster ⇒ template `Exists` **ở cluster đó**, cluster lạ `404 CLUSTER_NOT_FOUND`; không cluster ⇒ `Exists` ở ít nhất một cluster — `titan-ops features/catalog/design.md#template-per-cluster`), `GET /v1/vm-offerings`, `GET /v1/volume-offerings` (**anonymous** — trang công khai hiện giá, `titan-ops features/public-site/design.md#live-pricing`; **Titan DB catalog**, không đọc live provider) — hai endpoint offering trả **kèm giá** từ `titan-ops architecture/money-and-wallet.md#price-belongs-to-offering`. `IComputeCatalogProvider` (Incus impl từ INCUS-2 PR-2b) nay chỉ còn phục vụ os-images.
- **Sizing (`titan-ops features/catalog/design.md#vm-offering-sizing` + `titan-ops features/catalog/design.md#template-borrows-sizing`)**: template trả lời *"OS gì"*, VM offering trả lời *"to bằng nào"* (tier `s`/`m`/`l`/`xl`). CP resolve offering → truyền `cpuUnits`/`vcpuCount`/`memoryMb` xuống worker; worker Incus đặt `limits.cpu`/`limits.memory` của offering lên instance (`titan-ops features/catalog/design.md#catalog-resolution-at-create`). Offering **mang luôn giá của nó** — `vm_offerings.price_per_hour` `NOT NULL` (`titan-ops architecture/money-and-wallet.md#price-belongs-to-offering`); `PricingRule` đã bị gỡ.
  - 🔑 **`VmOffering` là nơi DUY NHẤT định nghĩa (cpu, vcpu, ram)** (`titan-ops features/catalog/design.md#template-borrows-sizing`). `VmTemplate` **không** còn `CpuUnits`/`VcpuCount`/`MemoryMb` — nó mang **FK `VmOfferingId`** (`NOT NULL`, `RESTRICT`) — lệnh sync template **không** mang sizing (`titan-ops features/catalog/design.md#template-is-an-image-alias`); khách chọn tier riêng cho VM. Nên FK này **không** ràng buộc lựa chọn của khách — đừng đọc nó như min-requirement (min-requirement đã bị Tôn Chủ BÁC, không phải chưa làm).
  - `GET /v1/templates` (khách) **không** có `cpu`/`vcpu`/`memoryMb` nữa, và **cũng không** có `vmOfferingId` — base sizing là chi tiết nội bộ. Chỉ `GET /v1/admin/templates` mang `vmOfferingId`.

- **Activity = request + outcome** (`titan-ops features/activity/design.md#request-and-outcome-names`): `*_requested` ghi ở handler (actor = người bấm); outcome (`vm.deleted`…) ghi ở **callback** qua `IActivityRecorder.StageOutcome(tenantId, …)` (tenant **của tài nguyên**, actor `system` — callback không có user). Hàng cũ giữ tên cũ (Tôn Chủ).
- Incus mapping (→ `CurrentState`, `titan-ops features/vm/design.md#status-mapping`): worker gửi `instance.Status` **nguyên văn** (`Running`/`Ready`/`Stopped`/`Frozen`/`Error`, không lọc, không cần IPv4); instance vắng ⇒ `exists:false` ⇒ `NotFound`, không bao giờ `Deleted` (trước INCUS-STATUS: map `status_code`, vắng ⇒ `Error`)
- 🔑 **Ghi `Status` có HAI loại luật** (`titan-ops architecture/intent-and-observation.md#intent-versus-observation`, `CM-7` đóng): **intent** (người bấm: `Vm.Rename`/`Network.RequestDelete`/`Tenant.Suspend`…) **throw** trong aggregate; **observation** (reconciler quan sát provider: `MarkObserved`/`MarkNotFound`…) **hội tụ, không throw**, và trạng thái đã-xoá là **terminal hấp thụ** (`IsTerminal`; VM: `CurrentExistence = Deleted` — chặn quan sát cũ hồi sinh VM đã xoá → tính tiền máy đã chết). Guard: `StateTransitionOwnershipTests.EveryStatusMutation_ValidatesInternally` (mọi mutation validate **nội tại**; quét cả `CurrentState`/`DesiredState` từ DESIRED-CURRENT-STATE; `NoInvariantAllowlist` = 3 dòng `VmTemplateCluster.MarkNotFound` · `ProviderCommand.Reopen` · `Vm.Accept`). Stop/Start/Delete **không** có transition để gộp guard nên aggregate **TRAO RA** provider id đã-validate (`D-7`) — guard nằm ở aggregate, **không** ở endpoint. Từ `titan-ops architecture/intent-and-observation.md#intent-has-identity` id đi kèm **vé intent** (`Vm.RequestStop()`/`RequestStart()`/`RequestDelete()`), và `CM-8` **đóng cho VM** (`PendingIntent`, xem bullet "Một yêu cầu, áp dụng một lần").

### Provider command keys
Khoá lệnh = chuỗi id workflow cũ (`titan-ops architecture/provider-and-worker.md#provider-command-key`).
- `vm-provision-{vmId}`, `vm-delete-{vmId}`
- `vm-stop-{vmId}-{intentId}`, `vm-start-{vmId}-{intentId}` — theo **lượt** (`titan-ops architecture/intent-and-observation.md#intent-has-identity`): lặp enqueue lại cùng khoá; stop→start→stop hợp lệ có khoá mới. Ba lệnh stop/start/delete ghi với `AfterFailureOnly`, cũng như `load-balancer.update` và hai lệnh backup; mọi lệnh khác giữ `AfterAnyFinish`
- `network-create-{networkId}`, `network-delete-{networkId}`
- `template-sync-{templateId}-{clusterId}` — một lệnh mỗi template mỗi cluster: khoá chỉ theo template thì cluster thứ hai đụng hàng mở của cluster đầu và bị nuốt (`titan-ops features/catalog/design.md#template-per-cluster`)
- `vm-snapshot-create-{snapshotId}`, `vm-snapshot-revert-{snapshotId}`, `vm-snapshot-delete-{snapshotId}`
- `load-balancer-create-{id}`, `load-balancer-update-{id}-{intentId}` (`AfterFailureOnly`), `load-balancer-delete-{id}`
- `vm-backup-{vmId}-{yyyyMMdd}`, `volume-backup-{volumeId}-{yyyyMMdd}` (`AfterFailureOnly`, ngày UTC, chữ số Gregorian): một bản mỗi ngày, lịch hỏi mỗi giờ (`titan-ops features/backup/design.md#incus-backup`)
