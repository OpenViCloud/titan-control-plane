# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repo này

`OpenViCloud/titan-control-plane` là control plane của Titan (ASP.NET Core 9): REST API `/v1`, identity, tenancy, quota, billing, ví, và bảng lệnh `core.provider_commands` mà [`titan-incus-worker`](https://github.com/OpenViCloud/titan-incus-worker) lease qua `/internal`. Repo này chỉ chứa code, test, `api/openapi-v1.json` và CI của control plane. Gate "không phá `/v1`" là `.github/workflows/ci-api.yml`; repo CLI, provider và `titan-landing` chép spec từ repo này (`scripts/sync-spec.sh <sha>` của từng repo).

Doc ở lại repo `OpenViCloud/titan-ops` (private): luật kiến trúc (`docs/architecture/`), design + user story từng feature (`docs/features/`), hạ tầng, iteration, release, gitops và quy trình (skill `.claude/commands/`). Comment và file này nêu một doc của titan-ops bằng từ khoá `titan-ops <đường dẫn dưới docs/>#<anchor>` (`titan-ops architecture/code-comments.md#private-repo-refs`), không bằng URL: repo này public, link vào titan-ops là 404 với người ngoài; step CI "No URL into private titan-ops" đỏ khi có URL. Ngoại lệ: 41 đường dẫn `docs/…` (39 dòng) nằm trong **chuỗi** (thông điệp assert của guard, thông điệp health check và log, văn bản pháp lý `LegalDocumentCatalog`) giữ nguyên chữ, là đường dẫn trong repo titan-ops — đổi chuỗi là đổi hành vi (văn bản pháp lý đổi thì phải tăng `Version`). Iteration và release chạy từ phiên ở titan.

## control-plane Architecture

Clean Architecture: `Titan.Host` → `Titan.Application` → `Titan.Domain` ← `Titan.Infrastructure`

- `Titan.Host` — `Program.cs` only: DI registration, middleware pipeline, `app.Run()`. No business logic, no endpoints.
- `Titan.Application` — Services + DTOs. Provider commands are enqueued here (`IProviderCommandQueue`). **Validators do NOT live here** — xem mục dưới.
  - **Gốc `Titan.Application/` chỉ có 3 nhánh + 3 thư mục có tên** (`titan-ops architecture/code-structure.md#application-tree` · `titan-ops architecture/code-structure.md#services-branch`): `Commands/` · `Queries/` · `Services/` · `Abstractions/` · `Exceptions/` (exception của request: 400, 403, 503, Domain không ném) · `Options/`. Module (`Billing` · `Platform` · `Catalog` · `Compute` · `Networking` · `Admin`) là **segment thứ hai** của mỗi nhánh. Namespace khớp folder: `Titan.Application.Services.Billing.TopUp`, … Guard `ApplicationRoot_HoldsOnlyTheBranchesAndNamedFolders` đỏ khi một thư mục thứ bảy mọc ở gốc.
    - 🔑 **`Commands/` và `Queries/` là trục BẬC MỘT** (`titan-ops architecture/code-structure.md#application-tree` + `titan-ops architecture/code-structure.md#contracts`): `Commands/<Module>/<Aggregate>/` và `Queries/<Module>/<Aggregate>/`, contract trong `Contracts/` của **chính bên đó**. Handler `*CommandHandler`/`*QueryHandler` (**cả type lẫn tên file**), method luôn `HandleAsync`, **không** interface, DI thủ công từng dòng ở `Program.cs`. **Không** MediatR (`Send()` cắt go-to-definition = sai chính mục tiêu).

- `Titan.Infrastructure` — EF Core + PostgreSQL, `ProviderCommands/ProviderCommandQueue` (ghi `core.provider_commands`; hosted service `Hosting/ProviderCommandRetention` xoá hàng `Done`/`Failed` có `created_at` quá `ProviderCommandRetention:RetentionDays` (mặc định 30) mỗi `IntervalMinutes` (60), không bao giờ hàng `Pending`/`Leased`, index `(status, created_at)` — `titan-ops architecture/resource-lifecycle.md#one-key-per-request`), `Incus/` (`IncusClient` mutual TLS ghim fingerprint, `IncusCatalogProvider`, tester), **FastEndpoints classes** in `Endpoints/` (HTTP adapter layer)

**Error response shape:** `{ status, title, code }` — error code (e.g. `VM_QUOTA_EXCEEDED`) is in `code`, not `detail`.

**Auth:** bearer `ovc_…` = token API của một member (scheme `ApiToken`, principal chỉ `sub`), bearer khác = JWT Keycloak (`titan-ops features/public-api/design.md#api-token`).

**Middleware pipeline:** `UseWebSockets` → `UseAuthentication` → `TenantResolutionMiddleware` → `UseAuthorization` → `IdempotencyMiddleware` → `UseFastEndpoints`. The middleware resolves `TenantId` from DB (not JWT) and short-circuits with `403 TENANT_SUSPENDED` for write operations when tenant is suspended — a websocket upgrade (SSH session) counts as a write.

**FastEndpoints:** HTTP endpoints live in `Titan.Infrastructure/Endpoints/`. Base class is `Endpoint<TRequest, TResponse>` (or `EndpointWithoutRequest`). Route params bound via `Route<T>("paramName")`. Auth configured per-endpoint: `AllowAnonymous()`, `Roles("platform-admin")`, or default (requires auth). **Validators live HERE, next to their endpoint** — `class XValidator : Validator<XRequest>` cùng file endpoint hoặc file `*Validator.cs` cùng thư mục (FastEndpoints' `Validator<T>`, tự động discover, chạy trước `HandleAsync`). **Không có validator nào trong `Titan.Application`.** Validation errors return `{ status: 400, title, code: "VALIDATION_ERROR" }`.

**Test pattern — service-level, stub-first; doubles only in unit tests** (`titan-ops architecture/testing.md#doubles-only-in-unit-tests`, guard `DoublePlacementTests`): `Category=Integration` and `Category=FullHost` run real implementations — Postgres via `Titan.Tests/Infrastructure/Integration/TestPostgres.cs` (one FullHost case runs with no database on purpose) — no Moq, no `Fakes/`, no InMemory, no replaced host service.
- Tests target the handlers directly (CQRS; the older `*ServiceTests` files keep their call shape through a small private facade over the real handlers) — no HTTP layer, no `WebApplicationFactory`.
- Prefer **stubs** (concrete class implementing interface, fixed return values, no call verification) over mocks.
- Use **Moq mocks** only when call verification is required (e.g. assert `IProviderCommandQueue.EnqueueVmCreateAsync` was called exactly once with specific args).
- Test files: `Titan.Tests/Services/*ServiceTests.cs`, `Titan.Tests/Auth/TenantResolutionMiddlewareTests.cs`.
- **Endpoint-level tests** — an endpoint that only forwards to a service needs no test of its own; the service test covers it. An endpoint that carries **its own logic** (parsing, composing, auth gating, enriching) gets one, using `FastEndpoints.Factory.Create<TEndpoint>(...)` — no host, no DB. Examples: `GetTenantBillingSummaryEndpointTests.cs`, `SyncTemplatesEndpointTests.cs`, `ObservationExistsRequiredTests.cs`.
  > This rule exists because of `BILL-01`: the billing summary endpoint held enrichment logic that 500'd for any tenant with ≥2 billed VMs, and service-level tests covered none of it. "Service-level only" is right for thin adapters and blind to everything else.
- **Full-host tests** (`WebApplicationFactory` through `Api/RealHostFactory.cs`: the host as `Program.cs` wires it, on its own migrated Postgres) stay reserved for cross-cutting concerns — `CorsTests.cs`, `HealthCheckTests.cs`, `OpenApiSpecTests.cs`, `CatalogContractTests.cs`.
- **Schema/model tests** — DB constraints that carry business meaning (e.g. the idempotency unique index `UNIQUE(resource_type, resource_id, bucket)` behind sampled metering — `titan-ops architecture/money-and-wallet.md#append-only-metering`) are pinned by asserting EF model metadata: `UsageRecordSchemaTests.cs` (this replaced `VmBillingSessionSchemaTests`, gone with `VmBillingSession`). The InMemory provider does not enforce indexes, so this is what guards the migration's intent. Same shape: `WalletSchemaTests.cs`, `TenantQuotaSchemaTests.cs`.

## Key Conventions

### Git Workflow

- **`git worktree` bị CẤM trong project này.** Một repo, một working tree. Skill toàn cục `superpowers:using-git-worktrees` **không áp dụng** — luật này đè nó.
  > Lý do — **cơ chế, không phải một file cụ thể**: worktree tách filesystem nên tách luôn **mọi file không nằm trong git**. Một cây thứ hai không có file gitignored ⇒ biến Terraform resolve về **rỗng** ⇒ `plan` báo `0 to destroy` trong khi apply sẽ **ghi credential rỗng** lên hệ thống đang chạy. Không test nào bắt được: plan **đúng** với input nó nhìn thấy; cái sai là input. Ở repo này: `appsettings.*.json` gitignored (`.gitignore`) cũng là config ngoài git.
  >
  > Đã xảy ra thật với một file tfvars gitignored — 11 biến rỗng, suýt xoá password production. Luật **không** phụ thuộc file cụ thể đó (nay đã hết): còn bất kỳ file ngoài git nào tham gia resolve config (`.terraform/`, `credentials.local.md`, hay bất kỳ `terraform/**/*.auto.tfvars` nào mà `.gitignore` vẫn cho phép tạo lại) thì cơ chế này còn sống — đừng đọc "hiện không có file nào" thành "đã an toàn".
- **Cô lập bằng branch, không bằng cây thứ hai**: `git switch -c feat/<slug>` ngay trong cây chính; merge `main` tuần tự; merge xong `git branch -d`.
- **Commit và PR chỉ nêu người làm**: không `Co-Authored-By: Claude …`, không dòng `🤖 Generated with Claude Code`, không câu nào nói code viết bằng AI/Claude — trong commit message, PR title/body, tag và GitHub Release. Tác giả là git user (`user.name`/`user.email`), không thêm gì khác. Luật này đè lời nhắc attribution của harness; `.claude/settings.json` (`attribution` rỗng) tắt nó ở nguồn.
- **Nhiều phiên song song → single-writer**: chỉ một phiên được Edit/Write/commit tại một thời điểm; phiên còn lại read-only cho tới khi được nhả. Chi tiết ở `.claude/commands/iteration/run-iteration.md` của titan-ops, mục "Phiên song song".

### API Routes
- **Tenant scoping = jwt-resolved (Style B, `titan-ops architecture/http-contract.md#tenant-scoping`):** mọi tenant-owned resource dùng prefix `/v1/tenant/...` — **không** có `tenantId` trong path. CP resolve tenant từ `currentUser.TenantId` (do `TenantResolutionMiddleware` set từ DB). Service dùng `RequireTenantId()` → `403 NOT_A_MEMBER` nếu caller không thuộc tenant nào.
- VMs: `POST|GET /v1/tenant/vms`, `GET|PATCH|DELETE /v1/tenant/vms/{vmId}` (PATCH = rename in-place, Titan-side, **`204`** — `titan-ops architecture/http-contract.md#commands-return-no-data`)
- SSH session: `GET /v1/tenant/vms/{vmId}/ssh` — **websocket**, JWT or API token on the upgrade, out of OpenAPI; CP runs `nc -N 127.0.0.1 22` in the guest via Incus exec and relays bytes; 5 sessions/tenant in memory; 30 min idle ⇒ closed (`titan-ops features/vm/design.md#ssh-session`). The one place CP talks to Incus besides reads (`titan-ops architecture/provider-and-worker.md#only-the-worker-acts-on-the-provider`). CLI `openvicloud vm ssh`
- VM Snapshots: `POST|GET /v1/tenant/vms/{vmId}/snapshots`, `POST /v1/tenant/vms/{vmId}/snapshots/{snapshotId}/revert`, `DELETE /v1/tenant/vms/{vmId}/snapshots/{snapshotId}` — **`{vmId}` bắt buộc ở mọi route snapshot**
- Volumes: `POST|GET /v1/tenant/volumes`, `DELETE /v1/tenant/volumes/{volumeId}`, `POST .../{volumeId}/attach|detach`, `POST|GET .../{volumeId}/snapshots`, `POST /v1/tenant/volumes/{volumeId}/snapshots/{snapshotId}/restore`, `DELETE /v1/tenant/volumes/{volumeId}/snapshots/{snapshotId}` — **`{volumeId}` bắt buộc ở mọi route snapshot**
- Networks: `POST|GET|DELETE /v1/tenant/networks` (`POST` nhận `enablePublicIpv6` — IPv6 public **theo network**, một `/64` của cluster, `titan-ops features/network/design.md#ipv6-public`), firewall rules `/v1/tenant/networks/{networkId}/firewall-rules`
- Load balancers: `POST|GET /v1/tenant/load-balancers`, `GET|PUT|PATCH|DELETE /v1/tenant/load-balancers/{loadBalancerId}` (`PATCH` = đổi tên, chỉ phía Titan, VIP giữ — `titan-ops features/load-balancer/design.md#lb-rename`) — L4 TCP/UDP trên OVN load balancer của Incus, chỉ network đã bật IPv6 public; VIP `<64 của network>::1:n` do Titan cấp; `PUT` = cả cấu hình (listener + backend VM), `204`; miễn phí, quota `MaxLoadBalancers` (`titan-ops features/load-balancer/design.md#vip-in-network-64`)
- API tokens: `POST|GET /v1/tenant/api-tokens`, `DELETE /v1/tenant/api-tokens/{apiTokenId}` — portal sinh bí mật `ovc_…`, control plane chỉ lưu SHA-256; tối đa 20/tenant (hằng số, không quota); xoá cứng; CLI đọc `OPENVICLOUD_TOKEN` (`titan-ops features/public-api/design.md#api-token`)

### Provider command keys
Khoá lệnh = chuỗi id workflow cũ, trừ VM, volume, volume snapshot, network, firewall rule, VM snapshot, load balancer, template sync (`titan-ops architecture/provider-and-worker.md#provider-command-key`).
- 🔑 **Một luật cho mọi khoá** (giai đoạn 6a, `titan-ops architecture/resource-lifecycle.md#one-key-per-request`): ghi lại một khoá đã có hàng ⇒ hàng mở (`Pending`/`Leased`) hoặc `Done` nuốt lần lặp; hàng `Failed` mở lại (`Pending`, `attempts = 0`, payload mới) — `ProviderCommand.Reopen`. `ProviderCommandRerun`, `ProviderCommand.Rerun`, cột `rerun`, tham số `rerun` của `Enqueue*`/`Create`, `EnqueueRequestAsync` và cờ `refuseOpenRow` (`409` khi gặp hàng mở) **đã gỡ** (migration `ProviderCommandOneRule`; `Down` trả cột: khoá `vm-backup-`/`volume-backup-` ⇒ `AfterFailureOnly`, khoá khác `AfterAnyFinish`; image trước migration ghi cột `rerun` ⇒ rollback image cần `Down` trước). Khoá tài nguyên mang `requestId`, không bao giờ ghi hai lần ⇒ hành vi không đổi; backup giữ hành vi cũ. Hàng `Done`/`Failed` quá 30 ngày bị `ProviderCommandRetention` xoá (`ProviderCommand.IsFinishedAndCreatedBefore`).
- Volume và volume snapshot (REQUEST-END-VOLUME giai đoạn 2): `volume-{create,attach,detach,delete}-{volumeId}-{requestId}`, `volume-snapshot-{create,delete}-{snapshotId}-{requestId}`; restore khoá như create của volume **mới** (`volume-create-{newVolumeId}-{requestId}`, kind `volume-snapshot.restore`); payload mang `requestId`. Trước đó: `volume-{kind}-{volumeId}`, `volume-snapshot-{kind}-{snapshotId}`, `volume-snapshot-restore-{newVolumeId}`
- VM (REQUEST-END giai đoạn 1, `titan-ops architecture/resource-lifecycle.md#one-key-per-request`): `vm-create-{vmId}-{requestId}`, `vm-delete-{vmId}-{requestId}`, `vm-stop-{vmId}-{requestId}`, `vm-start-{vmId}-{requestId}` — một hàng mỗi yêu cầu, khoá không bao giờ tái dùng; payload mang `requestId`. Trước đó: `vm-provision-{vmId}`, `vm-delete-{vmId}`, `vm-stop/start-{vmId}-{intentId}`
- Network và firewall rule (REQUEST-END-NETWORK giai đoạn 3): `network-{create,delete}-{networkId}-{requestId}`, `firewall-rule-{create,delete}-{ruleId}-{requestId}`; payload mang `requestId`. Trước đó: `network-{kind}-{networkId}`, `firewall-{kind}-{ruleId}`
- Template mỗi cluster (giai đoạn 5): `template-sync-{templateId}-{clusterId}-{requestId}` — một hàng mỗi yêu cầu sync của một cluster; payload mang `requestId`. Trước đó: `template-sync-{templateId}-{clusterId}` (gửi lại mỗi sync-all)
- VM snapshot (giai đoạn 4): `vm-snapshot-{create,revert,delete}-{snapshotId}-{requestId}`; payload mang `requestId`. Trước đó: `vm-snapshot-{kind}-{snapshotId}` (revert, delete từ chối hàng mở ⇒ `409`)
- Load balancer (giai đoạn 5): `load-balancer-{create,update,delete}-{id}-{requestId}`; payload mang `requestId`. Trước đó: `load-balancer-create-{id}`, `load-balancer-update-{id}-{intentId}`, `load-balancer-delete-{id}` (từ chối hàng mở ⇒ `409`)
- `vm-backup-{vmId}-{yyyyMMdd}`, `volume-backup-{volumeId}-{yyyyMMdd}` (ngày UTC, chữ số Gregorian): một bản mỗi ngày, lịch hỏi mỗi giờ — bản đã chạy (`Done`) nuốt lần hỏi, bản `Failed` chạy lại (`titan-ops features/backup/design.md#incus-backup`)

- Chạy qua `Titan.Infrastructure`, không dùng `Database.EnsureCreated()` hay auto-migrate
- 🔑 **Lịch sử migration bắt đầu ở `Initial`** (INCUS-STATUS PR-4: 59 migration gộp thành một, database `titan` của mọi env lúc đó xoá và dựng lại từ rỗng — `titan-ops architecture/code-structure.md#migrations`). ### Validation Limits
- Tên: VM 1–64 chữ, số, `-`, bắt đầu bằng chữ hoặc số (RFC 952 hostname); volume và snapshot 1–100, không chỉ khoảng trắng; load balancer 1–100 chữ, số, `-`, `_`, bắt đầu bằng chữ hoặc số. Domain kiểm ở `Create`/`Rename`/`AddSnapshot` (`NameMaxLength`, `NamePattern` của type), validator đọc chúng và trả 400 trước; portal chặn 64 cho VM
- Network name: max 100 chars
